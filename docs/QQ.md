# 可选 QQ 机器人

需要自己的 QQ 开放平台机器人、C2C 私聊权限与 **Node.js 24+**。程序使用官方 QQ API；无需公网回调监听。请遵守平台条款、用户同意、消息窗口及配额，不要用作群发或骚扰。

## 配置

示例字段见 `config/qq.env.example`，其中没有真实凭据。

### Windows

```sh
python qq_credentials.py --configure
```

程序会交互询问 AppID 和不回显的 AppSecret，使用当前 Windows 用户的 DPAPI 加密。开源版凭据位于 `%LOCALAPPDATA%/ToDoOpenSource/qq.credentials`，不在仓库中。已有凭据不会自动覆盖，迁移账户需重新配置。

第二台可通过 `--add-json` 从安全标准输入接收，格式为 `{"appId":"<APP_ID>","appSecret":"<APP_SECRET>"}`。不要将真实 JSON 放进命令行、命令历史或公开文件。配置成功不会回显密钥。

### Linux / 服务环境

通过服务管理器加载仓库外、仅服务用户可读的环境文件。单台使用 `QQBOT_APP_ID` / `QQBOT_APP_SECRET`；双台使用 `QQBOT_BOTS` JSON，槽位为 `bot-1` 与 `bot-2`。示例环境文件不能直接作为真实配置提交。

`QQBOT_PRIVATE_DIR` 必须指向仓库外的私有目录，保存接收人和配对状态；不能公开或复用于其他不受信任实例。默认目录为用户本地数据目录下 `to-do-open-source/qq-private/`。

## 启动与配对

确认已配置自己的凭据后，不带 `--no-reminders` 启动服务。生产环境仍需访问密码与 HTTPS 代理。

1. 打开 QQ 提醒页，为目标槽位生成一次性绑定码。
2. 在自己选择的机器人私聊会话中发送界面提供的 `/bind ...` 指令。
3. 确认该槽位已绑定，再主动发送测试提醒，核对 QQ 实际收到。
4. 第二台使用自己的码独立配对；不应将码分享给第三人。

普通聊天不会将第一个用户自动设为收件人。配对码短期有效且只能消费一次；已绑定状态下不能通过普通配对覆盖接收人。

## 数据与发送边界

- 提醒包含任务标题和截止时间，会发送至 QQ 平台及已绑定的账号。
- 机器人 AppID、密钥、令牌及收件人标识不会通过 HTTP 状态接口返回；配对码仅在授权配对响应中出现。
- 数据库保留调度和去重状态；不要公开数据库、私有状态文件或网关标准输入。
- 平台受理不等于送达或已读。配额耗尽、窗口失效或拒收时，不会伪装成发送成功。
- 两台机器人独立限流与调度；可能各自向同一任务发送提醒。
- 测试使用模拟 transport，不会连接真实 QQ。完整端到端确认需自己配置并授权发送。

不使用此功能时带 `--no-reminders`；还应清理进程继承的 `QQBOT_*` 环境变量，避免错误使用其他实例的配置。
